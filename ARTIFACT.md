# Artifact Description

For *Security Mediation and Adversarial Evaluation for Agentic AI in Scientific
Workflows*. This is the Artifact Description / Artifact Evaluation appendix,
kept in the repository so it stays true as the code moves.

---

## Contributions and artifacts

**C1 — SIEGE**, an attack corpus and harness for a deployed scientific agent,
including the HPC job-submission family and its scheduler-differential
methodology.

**C2 — PALISADE**, the mediation sidecar, in particular the G5 scheduler gate
and the G6 egress predicate.

**C3 — The evaluation protocol**: the soft-win/hard-win discrimination and the
production versus recorded-label decomposition.

**Computational artifacts.** The gate implementations, the 205-instance corpus
and its 181-task benign control with per-class ground truth, the ablation
harness, the adaptive drivers, and the analysis modules. One file is one
instance and one directory one class; the corpus is declarative and the runner
takes any gate stack exposing the same admission interface, so SIEGE runs
against defenses other than ours.

Two generated companions ship beside it:

- **`docs/palisade/corpus_datasheet.md`** — all 42 classes with per-class
  counts, provenance and authoring procedure, regenerated by
  `tools.corpus_datasheet` from the corpus itself.
- **`docs/palisade/README.md`** — the result-to-module map naming the analysis
  module behind each reported figure and table.

Both are checked by tests (`tools/tests/test_result_map.py`), so a claim in
either that stops being true fails the suite rather than rotting quietly.

## Availability

**Public.** The methodology, the gate implementations, the benchmark
instances, the benign controls, the analysis modules, and the
`job_submit.lua` facility policy. Public attack payloads are detection-pattern
triggers with placeholder hosts rather than working exploits, and all dual-use
content is surrogate-only — a claim checked by
`tools/tests/test_release_safety.py`, not merely asserted.

**Nothing is gated.** The adaptive machinery ships too — the trained attack
policies, the transform libraries, and the reward-ranked evasive pools. Gating
them was considered on the argument that together they constitute a turnkey
evasive corpus, and dropped: Section II-A argues that a defense evaluated only
against fixed attacks measures nothing about its worst case, and a reader
cannot check that against our own system with the attacks that move it held
back. **Every result here therefore reproduces**, including the reward-ranked
initialization of the adaptive drivers behind Section V-E, which no longer
needs a weaker public substitute. The transform libraries also drive a search
of the propagation closure — the experiment Section VI-A names as the one this
evaluation most obviously calls for; they are released for that purpose, and no
such experiment is reported here.

**Not redistributable.** MSTDB-TP is obtained under its own terms; we ship the
ingestion manifest and content hashes, not the database.

Exact per-path tiering, and the pre-publication checklist, are in
[`docs/palisade/RELEASE_SAFETY.md`](docs/palisade/RELEASE_SAFETY.md).

## Dependencies and host

**Everything runs on one workstation.** No result was produced on facility
infrastructure and no attack traffic was directed at a production system:
PALISADE is client-side, so reproduction needs no facility allocation and no
account. The Docker or Podman daemon the sandbox-mediation probe requires is
local, as is the `slurmctld` the parser-differential and B5 sweeps run against
— a containerized single-node controller shipped at Slurm 23.11.4.

The deterministic tier is CPU-only. Results were produced with **Python
3.14.3** under `uv`, pinned by `uv.lock`, against **AgentDojo v1.2.1** (PyPI
0.1.35). The G4 static-analysis tier runs the Semgrep ruleset bundled with the
sidecar (six rule files: code execution, credentials, environment-variable
manipulation, network, subprocess and typo-squatting) rather than one pinned to
an upstream registry, so `+semgrep` is reproducible without network access.

The cost figures of Section V-F and Table VI are single-node and
machine-dependent; ours is **Darwin arm64 with 10 cores**, which bears on
reproduction twice. Docker there runs containers inside a Linux virtual
machine, scoping the process-isolation result to that topology; and Python 3.14
on arm64 is the least-tested rung of our dependency stack.

## Served-model provenance

`gpt-oss-120b` is served **unfiltered** over an OpenAI-compatible endpoint on
the American Science Cloud (`api.i2-core.american-science-cloud.org`), reached
over the network from the workstation. The safety-filtered variant refuses
adversarial inputs and inflates the apparent block rate.

The slow tier is therefore **not** run inside a facility enclave: the
in-boundary endpoint that keeps untrusted and export-controlled content from
leaving is a deployment requirement we specify, not a property of these
measurements. Nothing sensitive transited that boundary, since payloads are
detection-pattern triggers and dual-use content is surrogate, so no real CUI or
export-controlled material reached the endpoint. A facility running the slow
tier on live scientific data would have to satisfy the enclave requirement
first, and our latency figures would move with its endpoint.

The same model occupies **every** model-backed role on both sides of the
evaluation: the quarantined slow tier, the LLM-judge comparator, and both
adaptive-attack proposers. No cross-family proposer was run, so the
shared-family confound Section V-E flags stands undiminished, and a
cross-family condition remains the first control we would add.

Endpoint configuration is recorded in `.env.sample`.

## Seeds and decoding

The static corpus is the deterministic stack at **seed 42**, exactly
reproducible without any endpoint. The `+slow` and `+all` columns pool five
live samples per instance, costing 1340 endpoint calls; the harness memoizes on
the inspected text, so 2785 of the 4125 lookups were served from cache.

Served PAIR and TAP runs report a **range over five seeds** rather than a
point — five being thin — and the objective-preservation verifier runs at
temperature 0.

**The artifact also runs fully offline**: with no endpoint configured, the
deterministic tiers and every fast-tier column reproduce exactly, and the
slow-tier columns degrade to a recorded stub rather than silently failing open.

## Reproduction

Every static-corpus result, the cumulative ablation, the per-boundary
decomposition, the soft/hard decomposition, the benign false-positive rates,
and the ladder rows not needing a served model reproduce offline and
deterministically in minutes to low hours on the single workstation above.

The scheduler-differential result and the full B5 sweep reproduce against the
shipped controller, all 55 submission instances driven through a live
`slurmctld` rather than a mocked scheduler.

Rows requiring the served endpoint (`+slow`, `+all`, the judge comparator, and
Table I's PAIR and TAP rows) reproduce only against an equivalent deployment,
and their reported **ranges**, not point equality, are what a re-run should be
checked against.

## Deviations from the paper's Appendix F

Recorded here because an AE reviewer will compare the two.

1. **Package layout.** The paper cites analysis modules as `tools.*`; they live
   at the repository root as `tools/`, run as `python -m tools.<module>` from a
   checkout, and are deliberately not packaged into the wheel.
2. **Naming.** The code was developed as `vistaguard` / `sciagentbench` and is
   released under the paper's names, `palisade` / `siege`. Environment
   variables are `PALISADE_<FIELD>`.
3. **Host coupling.** Five test files exercise PALISADE inside its reference
   deployment and require VISTA; they are under
   `src/palisade/tests/host_integration/` and skip automatically. Nothing the
   paper reports depends on them.
4. **The MCP tool manifest is frozen.** The corpus-realism checks normally
   AST-parse VISTA's live `mcp_servers/` tree. The standalone artifact ships a
   snapshot of the 21 tool contracts
   (`siege/src/siege/realism/mcp_tool_manifest.json`); the live tree wins when
   present.
5. **Payload scrub.** Four payload destinations naming real-world identifiers
   were replaced with reserved placeholders during release preparation, two of
   them live mining pools. See `docs/palisade/RELEASE_SAFETY.md`.
